## ① 빈 시간 추천과 재배치
- 일정 탭 → ‘빈 시간 추천 · 일정 재배치’, 또는 자비스에게 ‘빈 시간 추천해줘’라고 입력하세요.
- 시작 날짜, 1~14일의 계획 기간, 하루의 시작/종료 시각, 새 일정 이름, 15~720분의 소요 시간을 지정합니다. 기본 09:00~21:00는 수정 가능한 예시이며 사용자 생활 패턴을 추론한 값이 아닙니다.
- 로컬 일정과, Google이 연결됐다면 선택한 Google 캘린더의 바쁜 일정을 피해서 최대 세 가지 시간을 제시합니다. Google의 종일·여러 날 일정과 달력 시간대를 고려하고, 투명(시간 비움)/본인 참석 거절 일정은 바쁜 시간으로 세지 않습니다.
- 추천을 눌러 내용을 확인하기 전에는 저장하지 않습니다. 자료나 추천 시각이 바뀌었으면 다시 추천받아야 합니다.
- ‘기존 일정 재배치’를 펼쳐 **옮겨도 되는 로컬 일정만 직접 선택**합니다. 선택하지 않은 일정은 고정입니다. 변경 전/후를 확인하고 적용해야 옮깁니다.
- 빈 공간이 부족해 선택한 일정을 모두 넣지 못하면 아무것도 바꾸지 않습니다. Google에서만 존재하는 일정·종일 일정은 이동 대상이 아닙니다. Google에 이미 연결한 로컬 일정을 옮기려면 자동 반영을 켜야 합니다.
- 이 기능은 마감일·이동 시간·습관·우선순위를 자동 학습하지 않습니다. 매일 같은 가용 시간대를 쓰는 단순 계획입니다. 조회하지 않은 계정·캘린더·삼성 휴대폰 전용 일정은 알 수 없습니다.
- 선택한 Google 캘린더는 앞으로 90일의 읽기 범위입니다. 추천 기간이 범위 밖이면 Google을 연결한 상태에서 불완전한 자료로 추천하지 않고 거절합니다.

## ② Google 설정 — 반드시 본인 계정에서
Google Cloud 설정 및 OAuth 권한 동의는 아직 안 된 상태입니다. 이 단계 없이 실제 연동 성공으로 표시하지 않습니다.

1. https://console.cloud.google.com/ 에서 본인의 프로젝트를 선택/만듭니다. 본인 소유가 아닌 조직 프로젝트는 허락 없이 변경하지 마세요.
2. API 라이브러리에서 **Google Calendar API**를 사용 설정합니다.
3. Google Auth Platform / OAuth 동의 화면에서 앱을 구성합니다. 개인 시험용이면 테스트 사용자에 본인의 Google 계정을 추가하고, 권한과 테스트 앱 제한을 확인하세요. 다른 사용자에게 공개 배포하려면 Google의 검증·데이터 정책 요건을 별도로 충족해야 할 수 있습니다.
4. OAuth 클라이언트를 **Web application(웹 애플리케이션)** 유형으로 만듭니다.
5. **Authorized JavaScript origins**에 실제 사이트 origin을 등록합니다. 이 프로젝트의 경우 `https://seohu0426-maker.github.io` 입니다. 경로·쿼리는 넣지 않습니다. 로컬 시험을 직접 한다면 공식 안내에 따라 `http://localhost`와 사용하는 포트 origin도 추가합니다.
6. 생성된 **Client ID**(…apps.googleusercontent.com)를 사이트 설정 → Google · 삼성 캘린더 연동에 입력합니다. Client ID는 공개 앱 식별자이며 비밀번호/Client Secret/API 비밀 키와 다릅니다. **이 앱에는 비밀번호나 Client Secret을 입력하지 마세요.**
7. ‘Client ID 저장 · 연결 준비’를 누릅니다. Google 스크립트가 준비되면 ‘Google 로그인 · 일정 읽기/수정 권한’을 직접 눌러 계정과 권한을 선택합니다. 요청한 권한을 일부 거절하면 연결을 완료하지 않습니다.
8. 캘린더를 하나 선택하고 ‘지금 새로고침’으로 조회를 확인합니다. 읽기 전용 캘린더에는 쓰지 않습니다.
9. 삼성 캘린더에서는 같은 Google 계정의 해당 캘린더 동기화를 켭니다. **삼성 계정 전용이나 휴대폰에만 저장한 일정은 이 연결로 가져오지 않습니다.** 그 일정이 필요하면 사용자 판단으로 Google 캘린더에 옮기거나 별도의 Android Calendar Provider 연동을 개발해야 합니다. 이 버전은 삼성 전용 API에 접속하지 않습니다.

요청하는 OAuth 범위:
- https://www.googleapis.com/auth/calendar.calendarlist.readonly
- https://www.googleapis.com/auth/calendar.events
- https://www.googleapis.com/auth/calendar.events.freebusy

## 자동 연동의 정확한 범위
- Google → 화면: 선택한 캘린더의 앞으로 90일 일정을 별도 Google 일정으로 표시하고 추천에 활용합니다. Google 항목은 원본 앱에서 편집합니다. 로컬 일정으로 무조건 복제하지 않습니다.
- 화면 → Google: ‘이 앱 일정의 Google 자동 반영’을 **직접 켜고 확인**하면 현재 로컬 일정을 등록/갱신하고 이후 저장·수정·삭제도 반영합니다. **이미 Google에 있는 타인의/기존 일정 전체를 덮어쓰거나 재배치하지 않습니다.**
- 삭제는 이 앱이 해당 캘린더에 연결해 만든 일정만 대상으로 합니다. 연결 전 원래 있던 Google 일정은 수정/삭제하지 않습니다. 참석자를 추가하거나 초대 메일을 보내는 코드는 없습니다.
- Google에서 연결 일정이 외부 변경돼 ETag가 달라지면 덮어쓰기·삭제를 중단합니다. 자동 반영을 끄고 오류를 표시합니다. 이미 앞선 일정은 처리됐을 수 있으므로 ‘전체가 되돌려졌다’고 표시하지 않습니다. 충돌 버튼에서 Google 원본을 읽고 변경 전·후를 확인한 뒤 로컬 일정 1개를 원본에 맞출 수 있습니다. 이 동작은 Google 원본을 바꾸지 않습니다. Google에서 삭제되었거나 종일/여러 날로 바뀐 일정 등 로컬 형식과 맞지 않으면 자동 복구하지 않습니다. 자동 충돌 병합/일괄 되돌리기는 없습니다.
- 신규 등록은 로컬 ID와 캘린더·사이트 origin에 기반한 고정 Google ID를 사용해 불확실한 재시도에서 중복 등록 위험을 줄입니다. 기존 ID가 있더라도 내용·소유 연결 표시가 다르면 덮어쓰지 않습니다.
- **페이지가 화면에 열리고 OAuth 로그인이 유효한 동안만** 자동 갱신(약 5분)·쓰기를 시도합니다. 24시간 서버 작업이나 잠긴 휴대폰의 백그라운드 동기화를 구현한 것이 아닙니다.
- 토큰은 메모리에만 저장하므로 새로고침·재시작·만료 후 다시 로그인해야 합니다. 자동 반영은 매번 다시 켜야 합니다. Client ID·선택 캘린더 ID·Google-로컬 연결 기록·이동 허용 ID는 로컬 저장소에 보관합니다.
- 연결 해제 시 토큰과 읽은 일정 캐시를 메모리에서 지우고 Google 권한 취소를 요청합니다. 이미 Google에 저장한 일정은 지우지 않습니다. 필요하면 Google 계정 연결 관리에서도 권한 취소 여부를 확인하세요.
- 권한 취소·네트워크·Google 할당량·페이지 종료 시 미반영될 수 있습니다. 여러 탭 동시 편집과 서버 기반 지속 동기화는 미구현입니다. 동기화 메시지와 실제 Google 일정을 확인하세요.

## ④ Android 호출 — 별도 SOURCE ZIP
- `Jarvis-Android-Wake-0.5-SOURCE.zip`은 **APK가 아닌 실험 소스**입니다. GitHub Pages에 올릴 필요가 없습니다.
- Vosk 오프라인 한국어 모델을 사용한 스트리밍 인식, 지속 마이크 알림과 중지, 기본 비서 세션 요청을 작성했습니다.
- Android SDK/Gradle 부재로 컴파일·APK 생성·설치·실기기 시험을 수행하지 못했습니다. 한국어 모델도 포함하지 않았고, 별도 준비 스크립트로 공식 모델을 내려받아야 합니다. ‘자비스’ 고유명사 인식률도 미검증입니다.
- Android 12 이상 기기, 마이크·알림 권한, 기본 비서 선택, 사용자가 화면에서 직접 듣기 시작, 기기별 배터리/잠금 정책 확인이 필요합니다. 선택은 기존 비서에 영향을 줍니다. 무조건 호출 성공·잠금 자동 해제를 보장하지 않습니다.
- 남은 작업과 빌드/시험 순서는 Android ZIP 안 README.md를 보세요. 설치 가능한 완제품으로 안내하지 않습니다.

## 기존 기능
0.4의 이미지 음성 화면·기기 TTS 선택·화면 내 알람·백업은 유지합니다. 고급 외부 TTS/생성형 AI API는 연결하지 않았고, 화면 내 알람은 앱 닫힘/잠금 중 울리지 않습니다. 기존 0.3 일정 푸시 서버가 따로 운영되지 않으면 웹 푸시도 켜지지 않습니다. 이 ZIP에는 Node 푸시 서버가 포함되지 않았습니다. 새로운 요청에 없던 네이티브 정확한 알람 기능(③)은 추가하지 않았습니다.

## 개인정보
계정 비밀번호·Client Secret·OAuth 토큰을 소스나 로컬 저장소에 넣지 않습니다. 토큰은 Google API Authorization 헤더로만 보내고 Google 로그인 라이브러리를 동적으로 로드합니다. 자동 반영 동의 시 일정 제목·메모·시각·연결 식별자를 선택한 Google 캘린더로 전송합니다. 일정/알람 백업 및 로컬 저장소의 일정 정보는 암호화 저장이 아닙니다. 공개 저장소에는 실제 일정 백업·개인 비밀 설정·서명키를 올리지 마세요.

## 시험과 미검증
- 규칙 기반 계획 코어 단위 시험 5개: 겹침·경계, 바쁜/종일 시간 회피, 과거 시간 배제, 여러 이동 일정의 비충돌, 공간 부족, 잘못된 시간 길이 거절.
- 로컬 브라우저 통합: 읽기 페이지네이션, 모의 Google 바쁜/종일 일정 회피, 확인 전 무변경, 선택한 로컬 일정만 재배치, 동의 전 원격 무변경, Google 신규/수정/삭제, ETag 충돌 중단·확인 후 Google 원본으로 로컬 맞추기, 읽기 전용 보호, 만료, 토큰 미저장, 모바일/PC/다크 화면.
- 통합 시험은 **가짜 OAuth 토큰·모의 Google API**로 수행했습니다. 실제 계정 OAuth, Google API 운영, 삼성 동기화, Android 빌드·설치·화면 꺼짐 호출·음성 인식률·마이크/배터리, 실제 사이트 배포는 미검증입니다.
